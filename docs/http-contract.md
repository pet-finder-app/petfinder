# HTTP contract

The OpenAPI 3.1 contract is generated by Huma from the same route registry the server uses and from the Go request and response types; there is no hand-maintained YAML. Validation tags on JSON bodies are also enforced on requests; business rules and authorization stay in the handlers.

While the API runs, see `/openapi.yaml` or `/openapi.json`. To export it without starting the server or connecting to PostgreSQL:

```sh
make docs-generate
make docs-check
# optional destination, including stdout with -output -
go run ./cmd/openapi -output build/petfinder.yaml
```

`build/openapi.yaml` is a generated artifact ignored by Git. To change the contract, edit `internal/api/routes.go` and the types in `internal/api/contracts.go`, then regenerate. Database response models come from the SQLC code.

Collection routes accept `page` (from 1) and `page_size` (1 to 100) and answer `page.total` with the number of items across all pages. Errors use a problem object with `type`, `title`, `status`, `detail` and, for validation failures, `errors`. The `X-Request-ID` header correlates requests and logs.

After signing in, send the access token:

```http
Authorization: Bearer <access_token>
```

Access tokens last 15 minutes. The refresh token rotates on every renewal; passwords, refresh tokens and OTPs are stored only as hashes.
